Module Tw

Type-safe CSS styling

This module provides a typed interface for generating CSS styles without writing raw CSS. It prevents typos and invalid combinations at compile-time by using OCaml's type system.

Core Concepts

  • Utility-first: Instead of writing CSS classes with multiple properties, you compose small, single-purpose utilities (e.g., bg blue for background color, p 4 for padding)
  • Type-safe: The OCaml compiler catches errors like misspelled utilities or invalid value combinations at compile time
  • Composable: Styles are composed by creating lists of utilities that work together

How It Works

1. Each function returns a value of type t representing a single style 2. Multiple styles are combined by creating a t list 3. The list is converted to CSS using to_classes 4. The resulting string is used with HTML elements

Units and Scales

  • Spacing: Integer values create spacing in 0.25rem increments. 4 = 1rem = 16px (by default)
  • Sizes: Predefined sizes like sm, md, lg provide consistent scaling
  • Colors: Colors use an optional shade parameter (50-900) where higher numbers are darker

Usage Example

  let button =
    let styles =
      [
        (* Background and text colors *)
        bg blue;
        (* blue background *)
        text white;
        (* white text *)

        (* Spacing: padding of 1rem vertical, 2rem horizontal *)
        py 4;
        (* 4 * 0.25rem = 1rem *)
        px 8;
        (* 8 * 0.25rem = 2rem *)

        (* Typography and borders *)
        font_bold;
        (* font-weight: 700 *)
        rounded md;
        (* medium border radius *)

        (* Interactive states *)
        hover [ bg ~shade:700 blue ];
        (* darker blue on hover *)
        transition_colors;
        (* smooth color transitions *)

        (* Responsive design *)
        sm [ px 6 ];
        (* less padding on small screens *)
      ]
    in
    Html.button ~tw:styles [ Html.txt "Click Me" ]

    Colors

type t

The abstract type representing a single CSS style utility.

type color

Abstract type for colors. Use color constructors like red, blue, etc. Colors can have shades from 50 (lightest) to 900 (darkest).

Tailwind colors

Base colors map to the Tailwind v4 palette (shades 50–950). Use bg color shade, text color shade, and border_color color shade to produce utilities.

Palettes include: black, white, gray, slate, zinc, neutral, stone, red, orange, amber, yellow, lime, green, emerald, teal, cyan, sky, blue, indigo, violet, purple, fuchsia, pink, rose.

CSS Generation

This library generates Tailwind-like class names using to_classes.

Important: Class tracking and CSS file generation should be handled by the library user. For example, the Tw_html module collects all used Tw classes and generates the appropriate CSS file.

For dynamic styles that change at runtime, use to_inline_style to generate CSS properties directly for the style attribute.

val to_inline_style : t list -> string

to_inline_style styles generates inline CSS for the style attribute.

Note: This generates only the CSS properties for the given styles, without any Tailwind reset/prelude. The reset is only included in to_css since it's meant for complete stylesheets, not individual elements.

Perfect for tweaking individual HTML nodes with custom styles:

  (* Create inline styles *)
  let inline_styles =
    to_inline_style [ bg blue 100; p 4; rounded_md; text_white ]
  in

  (* Use in HTML *)
  Html.div
    ~at:[ Html.At.style inline_styles ]
    [ Html.txt "This div has inline styles" ]
  (* Generates: style="background-color:rgb(219 234
     254);padding:1rem;border-radius:0.375rem;color:rgb(255 255 255)" *)

When to use to_inline_style vs to_css:

Use to_inline_style when:

  • You need dynamic styles that change at runtime
  • You want to override specific styles on individual elements
  • You're working with existing HTML that you can't modify classes for
  • You need precise control over a single element's styling

Use to_css (preferred) when:

  • You want to generate a stylesheet that can be cached and reused
  • You're building a full website with consistent styling
  • You want better performance (CSS classes are more efficient than inline styles)

Performance considerations: Inline styles are significantly less performant for large-scale use compared to stylesheets because:

  • They increase HTML payload size (styles are repeated for each element)
  • They cannot be cached by the browser like external stylesheets
  • They have higher CSS specificity, making them harder to override
  • They don't benefit from CSS compression and minification

Use to_inline_style sparingly for dynamic or element-specific styling only.

val to_css : ?base:bool -> ?forms:bool -> ?mode:Css.mode -> ?layers:bool -> ?optimize:bool -> t list -> Css.t

to_css ?base ?forms ?mode ?optimize styles generates a CSS stylesheet for the given styles.

The generated CSS follows Tailwind's layering and ordering conventions:

1. Layer Order:

  • base: resets, preflight styles, and semantic element defaults
  • components: component classes (e.g., container or plugin-provided)
  • utilities: atomic utility classes (p-4, bg-red-500, etc.)

2. Utility Ordering (within utilities layer): Utilities are sorted by category in the following order:

  • Layout: position, display, float, clear, isolation, object-fit, overflow, overscroll
  • Flexbox & Grid: flex properties, grid properties, gap, order, place-content/items/self
  • Spacing: padding, margin, space-between
  • Sizing: width, height, min/max dimensions
  • Typography: font-family, font-size, font-weight, letter-spacing, line-height, text properties
  • Backgrounds: background-color, background-image, gradients
  • Borders: border-width, border-color, border-radius, border-style
  • Effects: box-shadow, opacity, mix-blend-mode
  • Filters: filter, backdrop-filter, blur, brightness, contrast
  • Tables: border-collapse, border-spacing, table-layout
  • Transitions & Animation: transition, duration, timing, delay, animation
  • Transforms: scale, rotate, translate, skew
  • Interactivity: cursor, user-select, resize, scroll-behavior
  • SVG: fill, stroke
  • Accessibility: sr-only, not-sr-only

Within each category, utilities maintain a stable order. Variants (hover:, sm:, etc.) are applied with responsive breakpoints in ascending order (sm → md → lg → xl → 2xl) and state modifiers in Tailwind's predetermined priority order.

Mode and base behavior

  • mode=Variables (default): emits layered output. When base=true, the Base layer (Preflight reset and semantic defaults) is included; when base=false, the Base layer is omitted but Theme/Components/Utilities layers remain present.
  • mode=Inline: resolves values and emits raw rules without any layers. In this mode, reset has no effect on layering.
  • parameter base

    Include base (Preflight) styles (default: true)

  • parameter forms

    Include forms plugin base styles. When true, adds base styles for native HTML form elements. When not specified, auto-detects based on utility classes (form-input, etc.)

  • parameter mode

    CSS generation mode (default: Variables)

Use this to generate your main stylesheet for inclusion in HTML <head>.
